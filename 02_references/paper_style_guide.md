# 优秀论文风格约束

本文件基于 `02_references/excellent_papers_style_signals.md` 的 OCR 结构索引整理，用于约束 Codex 的论文写作、图表审查和代码附录整理。

## 样本概况

- 样本数量：23 篇优秀论文。
- 年份范围：2024、2025。
- 页数范围：28 到 72 页。
- 平均页数：约 50 页。
- PDF 类型：扫描图像版为主，需要 OCR 读取。
- 轻量 OCR 策略：默认读取每篇前 3 页和后 2 页，用于提取摘要、开头结构和附录信号。

## 摘要写作约束

摘要必须采用“问题-方法-结果-结论”的竞赛式结构。不能只写研究背景，也不能只列算法。

推荐结构：

1. 第一段概述题目背景、核心任务和总方法。
2. 后续按“针对问题一、针对问题二、针对问题三”分述。
3. 每个问题都要写清：
   - 建立了什么模型；
   - 使用了什么求解方法；
   - 得到了什么关键结果；
   - 结果如何回答题目要求。
4. 摘要中应出现关键数值、排序、分类、参数、误差或评价指标。
5. 摘要最后给出模型亮点或推广价值。

禁止：

- 只有“本文建立模型并求解”这类空泛表述。
- 只描述算法名称，不给结果。
- 结果写成“较好、合理、有效”但不给证据。

## 问题分析约束

正文前部必须单独设置问题分析，并建议拆为：

- 问题的整体分析；
- 问题一的分析；
- 问题二的分析；
- 问题三的分析。

每个问题分析应说明：

- 输入数据是什么；
- 输出结果是什么；
- 核心困难是什么；
- 本问和其他问题的依赖关系；
- 为什么选择当前模型路线。

## 模型建立约束

每个问题的模型建立部分必须包含：

- 变量和参数定义；
- 数学表达式；
- 目标函数或评价指标；
- 约束条件；
- 求解流程；
- 与题目要求的对应关系。

如果模型含有多阶段步骤，应插入流程图。流程图可使用 TikZ、Mermaid、Python 或 imagegen 生成，但不得伪造数值结果。

## 结果分析约束

每个问题至少需要：

- 结果表；
- 一张服务结论的图；
- 对图表的解释；
- 与题目要求的直接回答。

图表不能孤立出现。正文必须明确说明“图/表说明了什么结论”。

## 检验分析约束

最终论文必须包含以下至少三类分析：

- 敏感性分析：核心参数扰动后结果是否稳定。
- 误差分析：数据误差、模型误差和数值求解误差。
- 鲁棒性检验：更换参数、扰动数据或比较模型时结论是否保持。

如果某一问没有显式参数，也要做替代检验，例如：

- 数据子集扰动；
- 随机种子扰动；
- 指标权重扰动；
- 基准模型对比；
- 消融实验。

## 图表约束

真实数据图：

- 必须由真实数据和可复现脚本生成；
- 由 Codex 负责最终配色、字体、线宽和 LaTeX 插入；
- 图题必须明确且使用中文；
- 坐标轴、图例、主要图内标注和单位必须使用中文；
- 题目领域缩写和统计指标缩写可保留，但正文或图注应有中文解释；
- 图中不放多余装饰。

版面约束：

- 优秀论文中的图表通常与正文交错出现，单张图尺寸克制，避免一页只放图。
- 子图允许用于同一结论下的对比，但最多两张；四宫格诊断面板不作为最终论文图使用。
- 普通数据图优先控制在 `0.58\textwidth` 到 `0.70\textwidth`，复杂图也不超过 `0.76\textwidth`。
- 单图不应占据约半页高度；若需要展示多项检验，应将多项数值放入表格，只保留最能说明结论的一张图。
- 图前或图后必须有解释文字，明确该图支持的结论和局限。

结构示意图：

- 可由 Codex 使用 imagegen skill 生成；
- 生成后必须保存到 `07_paper/figures/`；
- 必须服务模型说明；
- 不得包含学校、队伍或身份信息。

## 代码附录约束

代码附录必须体现可复现性，但正文附录不宜堆全部文件。

建议结构：

- 运行环境；
- 文件结构；
- 核心模型代码；
- 绘图代码；
- 完整代码文件说明。

代码整理要求：

- 删除“generated by AI”等痕迹性文字；
- 删除机械模板注释；
- 保留必要算法注释；
- 变量命名统一；
- 代码片段和正文结果一致；
- 完整代码保留在支撑材料目录。

## Codex 写作前检查

写入论文正文前，Codex 必须检查：

- 是否对照了 `scoring_rubric.md`；
- 是否参考了 `excellent_papers_style_signals.md`；
- 是否每一问都有方案审批、模型确认和图表审批；
- 是否每一张图都有来源和解释；
- 是否附录代码与正文结果一致。
